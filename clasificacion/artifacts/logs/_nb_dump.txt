Objetivo: crear tres `pandas.DataFrame` listos para un `Dataset` de PyTorch, con:

def build_split_dataframe(labels_csv: Path, images_dir: Path) -> pd.DataFrame:
    """Carga etiquetas RFMiD y resuelve la ruta de cada imagen de fondo de ojo."""
    labels = pd.read_csv(labels_csv)

    image_paths = [
        str(images_dir / f"{image_id}{IMAGE_EXTENSION}")
        for image_id in labels["ID"]
    ]

    split_dataframe = pd.DataFrame(
        {
            "image_path": image_paths,
            "disease_risk": labels["Disease_Risk"].astype(int),
        }
    )
    return split_dataframe


def count_missing_images(split_dataframe: pd.DataFrame) -> int:
    """Cuenta rutas que no apuntan a un fichero existente."""
    return sum(1 for path in split_dataframe["image_path"] if not Path(path).is_file())

> **Variante _sin recorte aleatorio_ de `other_experiments/02.1_train_resnet152.ipynb`.**
> Las entradas son siempre fondos de ojo **completos**: un `RandomResizedCrop(scale=(0.7, 1.0))` puede dejar fuera lesiones periféricas, el disco óptico o la mácula, y además deforma la proporción de la imagen. Aquí se sustituye por un **letterbox** (lado largo = `image_size`, relleno negro hasta cuadrado), aplicado **igual en train, val, test y Grad-CAM** (`TrainConfig.preprocessing = "letterbox"`).
> Se reutilizan **los mismos hiperparámetros de Optuna** (`best_params.json`, encontrados con el recorte aleatorio) y las mismas épocas, de modo que la única diferencia con el original es el preprocesado. Los modelos originales (`best_resnet152_disease_risk.pt` y `..._optuna.pt`) **no se reentrenan ni se modifican**: se cargan y se evalúan con *su* preprocesado original. Si falta alguno (incluido el baseline nocrop de `02_train_resnet152_nocrop.ipynb`), se omite de la comparación con un aviso.
> Salidas con sufijo `_nocrop`: checkpoint `best_resnet152_disease_risk_optuna_nocrop.pt`, historial `artifacts/logs/tuned_nocrop_history.json`, figuras `artifacts/figures/tuned_nocrop_*.png` y Grad-CAM en `artifacts/gradcam/nocrop/`.

# RFMiD — ResNet-152 con los hiperparámetros de Optuna (Disease_Risk), sin RandomResizedCrop

1. Carga los mejores hiperparámetros de `artifacts/optuna/best_params.json` (notebook `03`).
2. Entrena el modelo final: `train_loss` y `val_loss` por época, *early stopping* y checkpoint por **`val_loss` mínima** (no por AUC) en un archivo **nuevo** (`best_resnet152_disease_risk_optuna_nocrop.pt`), sin tocar los anteriores.
3. Evalúa en **test**; el umbral de decisión se elige **solo en validación** (índice de Youden) y se compara: baseline original, ajustado original, baseline nocrop y ajustado nocrop.
4. Grad-CAM sobre el modelo ajustado nocrop.

**Criterio de selección = `val_loss` (se minimiza).** El mejor checkpoint y el *early stopping* (paciencia 7) usan la pérdida focal de **validación** (`selection_metric="val_loss"`). Se descarta `train_loss` porque baja casi siempre con las épocas y elegiría la más sobreajustada; `val_loss` sí mide generalización. Como el scheduler ajustado de Optuna es `ReduceLROnPlateau`, en esta variante monitoriza también `val_loss` (modo `min`) para que LR, checkpoint y *early stopping* usen la misma señal (en el resto de notebooks sigue monitorizando el AUC). AUC, F1 y accuracy se siguen calculando y reportando como métricas de evaluación, y el umbral de decisión se sigue eligiendo solo en validación.

**Nota de cómputo:** sin GPU (CPU, 4 hilos). Con `layer3` descongelado una época a 224 px tarda ~20 min, así que el entrenamiento final se limita a **10 épocas** (`EPOCHS_FINAL`), igual que en `other_experiments/02.1_train_resnet152.ipynb`.

## 3. Evaluación: baseline vs ajustado, original vs nocrop

Se calculan las probabilidades de cada modelo en val y test, **con el preprocesado con el que fue entrenado** (resize cuadrado para los originales, letterbox para los nocrop). El **umbral se elige en validación** (índice de Youden: maximiza TPR − FPR, más adecuado que F1 con 79 % de positivos) y se aplica sin cambios a test. Se incluye también el umbral fijo 0.5. El AUC no depende del umbral.
--- [9] code

model_configs = {
    "baseline (original)": baseline_config,
    "ajustado (original)": tuned_config,
    "baseline nocrop": baseline_nocrop_config,
    "ajustado nocrop": tuned_nocrop_config,

    PREPROCESSING_RANDOM_CROP: (original_val_loader, original_test_loader),
    PREPROCESSING_LETTERBOX: (val_loader, test_loader),

TUNED_NOCROP_NAME = "ajustado nocrop"

predictions = {}
tuned_model = None
for model_name, model_config in model_configs.items():
    checkpoint_path = model_config.checkpoint_dir / model_config.best_checkpoint_name
    if not checkpoint_path.is_file():
        print(f"AVISO: no existe {checkpoint_path}; '{model_name}' se omite de la comparación.")
        continue

    model = load_model(checkpoint_path, model_config, device)
    model_val_loader, model_test_loader = evaluation_loaders[model_config.preprocessing]
    val_probabilities, val_labels, _ = collect_predictions(model, model_val_loader, device)
    test_probabilities, test_labels, _ = collect_predictions(model, model_test_loader, device)
    predictions[model_name] = {
        "val_probabilities": val_probabilities,
        "val_labels": val_labels,
        "test_probabilities": test_probabilities,
        "test_labels": test_labels,
        # Umbral elegido SOLO con validación
        "threshold": select_threshold_youden(val_probabilities, val_labels),
    }
    print(f"{model_name}: umbral (Youden, val) = {predictions[model_name]['threshold']:.3f}")

    # Solo se conserva en memoria el modelo que se usará en Grad-CAM
    if model_name == TUNED_NOCROP_NAME:
        tuned_model = model
    else:
        del model

## Grad-CAM: ¿en qué se fija el modelo?

Grad-CAM (implementado a mano en `src/explain.py`) usa los *hooks* de la última capa convolucional (`layer4[-1]`): pondera cada mapa de activación por la media de su gradiente respecto al **logit de Disease_Risk** y aplica ReLU. El resultado es un mapa de calor de las regiones que *empujan* la predicción hacia "riesgo".

Se muestran ejemplos del **test** (umbral 0.5, el de las métricas de arriba): los verdaderos positivos (TP) y negativos (TN) más confiados, y los errores más confiados (FP y FN). Las imágenes se preprocesan con el **mismo letterbox** que usó el modelo (`preprocessing=config.preprocessing`); por eso las bandas negras superior/inferior son relleno. Las figuras se guardan en `artifacts/gradcam/nocrop/`.

# RFMiD — subir el recall de `Disease_Risk` sin perder accuracy, F1 ni AUC

**Contexto médico.** Es un cribado: un falso negativo (paciente con riesgo que el modelo da por sano) es peor que un falso positivo. El objetivo es que el **recall de la clase enfermo** (sensibilidad) esté **cerca de 0.90 tanto en validación como en test**, manteniendo accuracy, F1 y AUC.

**Punto de partida:** el ResNet-152 ajustado con Optuna y entrenado con *letterbox* (sin recorte aleatorio) de `02.1_train_resnet152_nocrop.ipynb`, evaluado a umbral 0.5 y al umbral de Youden de validación (como en 02.1).

**Plan por etapas (se para en cuanto se cumple el objetivo):**
1. **Umbral de decisión elegido en validación**: el mayor umbral cuyo recall de validación sea ≥ objetivo (+ un pequeño margen). Es el método estándar y no cuesta nada; el AUC no cambia porque no se toca el modelo.
2. **TTA** (volteo horizontal y rotaciones ±10°) y **ensemble** (media de probabilidades) de los ResNet-152 ya entrenados, cada uno con su preprocesado. Miembros y variante final se eligen **solo con el AUC de validación**.
3. Búsqueda Optuna orientada a recall + reentrenamiento: solo si 1–2 no bastan (ver sección correspondiente).

**Reglas anti-fuga:** umbral, miembros del ensemble y variante final se deciden con **validación**; test solo se usa para informar las métricas finales (con IC 95 % bootstrap, 1000 remuestras, umbral fijo).

## 9. Conclusión

**¿Se alcanzó el recall ≈ 0.90? Sí, en validación y en test, sin tocar ni reentrenar ningún modelo.** La etapa 3 (Optuna + reentrenamiento) **no se ejecutó** porque las etapas 1–2 ya cumplían el objetivo (ver la celda de comprobación); lanzarla habría costado horas de CPU y más riesgo de sobreajustar una validación de solo 640 imágenes (134 sanos).

**Método final** (todo elegido con validación): media de probabilidades de los 4 ResNet-152 (cada uno con su preprocesado) con TTA de 4 vistas (original, volteo horizontal, rotación ±10°), y umbral de decisión **0.399** = mayor umbral con recall de validación ≥ 0.91 (objetivo 0.90 + 0.01 de margen).

**Resultado en test** (IC 95 % bootstrap, umbral fijado en validación), frente a la referencia (`ajustado_nocrop`, umbral 0.5):

| | Referencia (0.5) | **Final** |
|---|---|---|
| Recall (sensibilidad) | 0.868 [0.836, 0.893] | **0.929** [0.906, 0.951] |
| Especificidad | 0.955 [0.913, 0.986] | 0.881 [0.824, 0.931] |
| Precisión | 0.987 [0.975, 0.996] | 0.967 [0.950, 0.981] |
| Accuracy | 0.886 [0.859, 0.908] | **0.919** [0.897, 0.939] |
| F1 | 0.923 [0.904, 0.939] | **0.948** [0.933, 0.961] |
| AUC | 0.968 [0.953, 0.978] | 0.971 [0.958, 0.981] |
| FN / FP | 67 / 6 | **36** / 16 |

El recall en validación es 0.911 (objetivo del umbral) y en test 0.929. El margen de 0.01 deja el recall de test algo por encima de 0.90; la variante **sin margen** (recall de validación ≥ 0.90, umbral 0.416) da test recall 0.913, especificidad 0.888, accuracy 0.908 y F1 0.940: es la alternativa si se prefiere ceñirse más al 0.90.

**Qué ha costado y qué no:**
- **Recall: +6.1 puntos** (IC pareado [+4.3, +8.4]): de 67 a 36 falsos negativos sobre 506 enfermos.
- **Especificidad: −7.5 puntos** (IC pareado [−12.2, −3.7]) y precisión −1.9 puntos: de 6 a 16 falsos positivos sobre 134 sanos. Este es el precio real y es significativo; no hay forma de subir el recall sin pagarlo, porque mover el umbral solo desplaza el punto sobre la misma curva ROC.
- **Accuracy y F1 suben** (+3.3 y +2.4 puntos, ICs que no incluyen 0), no bajan, porque el 79 % de las imágenes son enfermas y los positivos pesan más en ambas métricas. No es una mejora del modelo sino del punto de operación.
- **AUC: +0.003, dentro del ruido** (IC pareado [−0.002, +0.009]). El AUC no depende del umbral; el ensemble + TTA solo aporta una mejora pequeña y no demostrable. La etapa 1 (solo el umbral) ya daba casi todo el beneficio (test: recall 0.923, accuracy 0.911, F1 0.942); el ensemble/TTA añade ~+0.006 de recall y ~+0.015 de especificidad a igual criterio de validación, también dentro de los IC.

**Falsos negativos que quedan (36):** sus probabilidades están en 0.15–0.40 (mediana 0.29), 17 de ellos "por poco" (≥ 75 % del umbral). Se concentran en **ODC** (cupping del disco óptico, 17 de 91 casos perdidos, 19 %) y **DN** (7 de 46, 15 %); DR (3/124) y MH (2/104), que son las más frecuentes, casi no se pierden. Los Grad-CAM de los FN más confiados muestran fondos de ojo de aspecto normal a 224 px, mapas de calor sobre el borde/relleno negro o sobre el disco óptico sin una lesión evidente: son hallazgos sutiles (el cupping se aprecia mal a baja resolución). Una mejora real probablemente exigiría más resolución o más datos de esas clases, no solo mover el umbral (no se ha probado aquí).

**Salvedades.** (1) Todo se eligió con validación; test solo informa, pero la elección entre 4 variantes y 15 subconjuntos usa la misma validación de 640 imágenes: las diferencias de AUC entre variantes (< 0.01) están dentro del ruido, por eso se priorizó el ensemble más grande. (2) La especificidad de validación (0.776) es mucho menor que la de test (0.881): los 134 sanos de validación resultan más difíciles, y los IC de especificidad son amplios (±0.05). (3) El IC bootstrap mide solo la incertidumbre del tamaño del test con el umbral ya fijado, no la de elegirlo. (4) Los 4 modelos se evalúan con los preprocesados con los que se entrenaron (resize cuadrado / letterbox).

### Lectura cualitativa (baseline, test)

- **TP:** el calor se concentra en la **región central/macular y paramacular**, de forma amplia y difusa. Cuando hay lesiones visibles (exudados amarillos, hemorragias) el calor las cubre, pero en imágenes borrosas u opacas (medios turbios) se activa sobre casi todo el disco central: el modelo parece usar también *calidad/aspecto global de la imagen* y no solo lesiones localizadas.
- **TN:** activación casi nula en todo el fondo de ojo. Son retinas nítidas con disco óptico, vasos y mácula normales; no hay evidencia a favor de "riesgo" (el mapa solo explica la clase positiva).
- **FP:** el calor cae en **zonas concretas del interior** (arcos vasculares, parte superior/lateral) con probabilidades moderadas (0.60–0.81): variaciones de iluminación o textura que el modelo confunde con patología.
- **FN:** el calor se va **a las esquinas / el borde del campo** (fuera de la retina útil) o a zonas sin lesión; p. ej. la imagen 166 tiene una lesión anular visible en la mácula y el modelo no la mira. Son casos de patologías sutiles que el modelo no capta, y señalan cierta dependencia de artefactos del borde.

Conclusión: el modelo se centra en la retina central (donde está la patología más habitual) y casi nunca en el disco óptico por sí solo; los errores se asocian a artefactos de borde, iluminación y patologías sutiles. Grad-CAM es cualitativo: sirve para detectar atajos, no para demostrar que el modelo razona como un clínico.

# RFMiD — búsqueda de hiperparámetros con Optuna (ResNet-152, Disease_Risk)

**Objetivo:** maximizar el **AUC de validación**.

**Sin fuga de datos:** cada trial ajusta los pesos con *train* y se puntúa **solo con *validación***. El conjunto de *test* no se carga en ningún momento de este notebook (`src/tuning.py` no lo lee); queda reservado para la evaluación final en `02.1_train_resnet152.ipynb`.

## Presupuesto de cómputo (régimen reducido)

Esta máquina **no tiene GPU** (solo CPU, 4 hilos). Medido: una pasada forward+backward de 16 imágenes a 224 px cuesta ~3.1 s con `layer4` entrenable y ~6.6 s con `layer3+layer4`, es decir, ~11 min por época completa (train + val) a 224 px. Entrenar 20 épocas por trial es inviable, así que **cada trial usa un régimen reducido**:

| Ajuste | Valor | Motivo |
|---|---|---|
| Tamaño de imagen | 160 px (el final usa 224) | ~2x más rápido |

## Espacio de búsqueda y justificación

| Hiperparámetro | Rango | Por qué |
|---|---|---|
| `learning_rate` | 1e-5 … 1e-3 (log) | El baseline usa 1e-4; la escala es multiplicativa, de ahí la búsqueda logarítmica. |
| `weight_decay` | 1e-6 … 1e-2 (log) | Regularización de AdamW; con ~2k imágenes y `layer4` (~15 M parámetros) el sobreajuste es el riesgo principal. |
| `focal_gamma` | 1.0 … 3.0 | Cuánto se ignoran los ejemplos fáciles; 2.0 es el valor estándar, se explora a ambos lados. |
| `focal_alpha` | 0.15 … 0.75 | Peso de la clase **positiva** (Disease_Risk=1, ~79 % de los datos). Un peso balanceado por frecuencia inversa sería ≈ 0.21 (el baseline 0.25 ya está ahí), pero el AUC no depende de un umbral y a veces gana pesar más la clase mayoritaria, así que se explora hacia arriba. |
| `batch_size` | 8 / 16 / 32 | Ruido del gradiente vs. estabilidad de BatchNorm; lotes pequeños dan más actualizaciones por época. |
| `unfreeze_layer3` | False / True | Más capacidad de adaptación al dominio de fondo de ojo (imágenes muy distintas de ImageNet) a cambio de coste y más riesgo de sobreajuste. |
| `lr_scheduler` | none / cosine / plateau | `none` = baseline; `cosine` decae suavemente; `plateau` reduce el LR a la mitad si el AUC se estanca 2 épocas. |

**Excluido:** la fuerza de *data augmentation*. Con un 50 % de train y 4 épocas su efecto no se puede medir de forma fiable, y se mantiene la augmentation del baseline.

**Sampler / pruner:** `TPESampler(seed=42)` (reproducible) y `MedianPruner` con `trial.report` del AUC de validación tras cada época (3 trials de arranque sin podar y sin podar la primera época). # RFMiD — comparación de arquitecturas (Optuna por modelo + Grad-CAM)

Compara varias arquitecturas ImageNet de `torchvision` en **Disease_Risk** (binario, ~79 % positivos). Cada una tiene **su propio estudio Optuna** (objetivo: **AUC de validación**) y se reentrena con sus mejores hiperparámetros. El **ResNet-152** del proyecto entra como referencia: se reutiliza su checkpoint, **no se reentrena**.

**Sin fuga de datos:** Optuna solo ve *train* (ajuste) y *validación* (puntuación); el umbral de decisión se elige **solo en validación** (índice de Youden) y se aplica sin cambios a *test*. El *test* se usa únicamente para informar métricas y para elegir las imágenes ilustrativas de Grad-CAM.

## Modelos y por qué

| Modelo | Params (M) | GFLOPs | Motivo |
|---|---|---|---|
| **ResNet-152** (referencia) | 58 | 11.5 | Baseline del proyecto; se reutiliza su checkpoint. |
| **ResNet-50** | 24 | 4.1 | Misma familia residual con ~3x menos capas (50 vs 152): aísla el efecto de la **profundidad** y es una referencia mucho más barata en CPU. Su `layer4` tiene los mismos ~15 M de parámetros que el del ResNet-152 → capacidad de *fine-tuning* comparable. |
| **DenseNet-121** (pedido) | 8 | 2.9 | Conexiones densas que reutilizan rasgos de baja y alta resolución; muy usada en imagen médica (CheXNet). Pocos parámetros → buena para ~2k imágenes. |
| **EfficientNet-B0** | 5 | 0.4 | Escalado compuesto, el modelo más ligero: ¿basta un modelo pequeño con tan pocos datos? Es el más barato de entrenar. |
| **ConvNeXt-Tiny** | 28 | 4.5 | CNN "modernizada" con receta de Transformer (LayerNorm, convoluciones 7x7 *depthwise*, GELU); mejor precisión en ImageNet (82.1 %) que las anteriores. Mantiene mapas 2D, así que **Grad-CAM se aplica directamente**. |

**Descartados:** Swin-T / ViT (la atención con ventanas o parches exige reconstruir el mapa 2D desde tokens y el tamaño de entrada fijo; Grad-CAM deja de ser directo) y RegNet (muy parecido a ResNet, aporta poca diversidad). Mantener 4 modelos nuevos mantiene el coste razonable en CPU.

## Política de congelación

En todos: backbone congelado; se entrenan la **cabeza** (1 logit) y los **últimos `unfrozen_blocks` grupos de bloques** (cada grupo = etapa + el *downsampling* que la precede). `unfrozen_blocks` es un hiperparámetro de Optuna (1 … N). Se describe por modelo en la tabla de más abajo.

## Arquitecturas: parámetros entrenables y capa de Grad-CAM

Capa objetivo de Grad-CAM = **última capa con mapa espacial 2D** (justo antes del *pooling* global y la cabeza):

| Modelo | Capa Grad-CAM | Grupos descongelables (del final hacia atrás) |
|---|---|---|
| ResNet-50 / 152 | `layer4[-1]` (`layer4.2`) | `layer4` · `layer3` |
| DenseNet-121 | `features.norm5` (salida de `denseblock4` normalizada) | `norm5 + denseblock4 + transition3` · `denseblock3 + transition2` |
| EfficientNet-B0 | `features.8` (conv 1x1 final, 1280 canales) | `features.8 + 7` · `features.6` · `features.5 + 4` |
| ConvNeXt-Tiny | `features.7` (etapa 4) | `features.7 + 6` · `features.5 + 4` |

*Nota DenseNet:* `torchvision` aplica un `ReLU` *in-place* tras `norm5`, así que el gradiente que captura el hook es el de la pre-activación (enmascarado por el ReLU). Es la variante habitual de Grad-CAM para DenseNet, pero los mapas no son idénticos al Grad-CAM "puro" de los demás.

## 2. Optuna: un estudio por arquitectura

**Objetivo:** maximizar el AUC de validación (mejor valor alcanzado en el trial). **Sampler:** `TPESampler(seed=42)`. **Pruner:** `MedianPruner(n_startup_trials=3, n_warmup_steps=1)` con `trial.report` tras cada época. El trial 0 de cada estudio es el **baseline** (`lr=1e-4`, `wd=1e-4`, `gamma=2`, `alpha=0.25`, batch 16, 1 grupo descongelado, sin scheduler) para tener una referencia en el mismo régimen reducido.

| Hiperparámetro | Rango | Nota |
|---|---|---|
| `learning_rate` | 1e-5 … 1e-3 (log) | Escala multiplicativa. ConvNeXt suele preferir LR menores; TPE lo descubrirá. |
| `weight_decay` | 1e-6 … 1e-2 (log) | Regularización de AdamW. |
| `focal_gamma` | 1.0 … 3.0 | Cuánto se ignoran los ejemplos fáciles. |
| `focal_alpha` | 0.15 … 0.75 | Peso de la clase positiva (Disease_Risk = 1). |
| `batch_size` | 8 / 16 / 32 | Ruido del gradiente vs. estabilidad de BatchNorm. |
| `unfrozen_blocks` | 1 … N (N = 2 salvo EfficientNet-B0, N = 3) | Capacidad de adaptación al fondo de ojo vs. coste/sobreajuste. |
| `lr_scheduler` | none / cosine / plateau | `plateau` reduce el LR a la mitad si el AUC no mejora en 2 épocas. |

Cada estudio guarda `artifacts/optuna/compare_<modelo>.db` y, al terminar, `artifacts/optuna/compare_<modelo>_best_params.json`.
